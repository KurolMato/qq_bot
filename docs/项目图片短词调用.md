# 项目图片短词调用

在允许的群里 @机器人后直接说下列短词，调用原有功能生成图片。不需要“能不能发一下”，也不发送确认或排队提示。

| 短词示例 | 原有入口 |
| --- | --- |
| 排行、排名、排行榜、rank | `/rank` |
| 昨日排行、周榜、月榜 | `/rank y/w/m` |
| 9月排行 | `/rank m 9` |
| 我的排名、个人档案 | `/rank me` |
| 我的今日排行、我的周榜 | `/rank me d/w` |
| 我的9月档案 | `/rank me 9` |
| 另一组排行、另一组周榜 | `/rank o`、`/rank o w` |
| 在线、谁在线、在线列表 | `/game ol` |
| Steam列表、PSN列表（也可 PS5）、Switch列表、Xbox列表 | 对应平台的 `list` |
| 发售日历、本月发售日历 | `/game list` |
| 发售日历 9、9月发售日历 | `/game list 9` |
| 发售日历 2027-9、发售日历 2026 | 指定月份日历、年度拼图 |
| 游戏进度 黑神话悟空、成就进度 Elden Ring | `/game 游戏名`，群内 Steam 成就进度卡 |
| 指令图、帮助、菜单、使用说明 | 现有指令说明图片 |

短词和简单口语仍直接调用；未命中固定规则时，启用 DSH 的群聊和私聊会让模型理解自然表达，并选择本页已有的图片功能。例如“大家这会儿都在玩啥”可选择在线总览，“把这个月要出的游戏给我瞅瞅”可选择本月发售日历，“今天谁玩得最久”可选择今日排行。自然语言路径需要等待模型，短词路径不需要。

模型只输出结构化图片请求，程序严格验证功能名、平台、月份和查询参数后再调用原有入口。不能指定任意文件、群号、用户号或管理命令；添加、删除账号或游戏等操作不在图片路由中。超时、取消或错误轮次不会执行图片请求，模型内部标记不展示给用户。

群里仍需 @机器人；明确的请求不必带问号，单纯问候保持原来的忽略行为。普通聊天正常回答，缺少游戏名或意图不明确时追问，不发送“已收到”等固定确认话术。自然语言理解依赖模型，模拟测试验证调用流程与参数边界，不代表所有表达都能准确识别。

私聊白名单用户可以使用同样的短词。只有一个允许群时自动选择该群；有多个群时使用“群号 123456 排行”指定数据范围，图片仍发回私聊，不往群里发。只允许配置范围内的群；个人图按提问者 QQ 的群内绑定查询。

现有图片生成、无数据提示、平台配置及群权限检查都沿用原功能。HLTB 当前是文字结果，不属于图片入口；自动解析链接的图文仍由原链接解析功能处理。

重启机器人后生效，无新增依赖。本次功能运行所需变更文件：

- `qq_bot/project_images.py`（新增）
- `qq_bot/group_rules.py`
- `qq_bot/group_dsh.py`
- `qq_bot/dsh_commands.py`
- `qq_bot/group_usage.py`

依赖原有各平台命令、排行榜、游戏日历、成就卡及 `assets/instruction.png`，这些资源没有改动，不需要替换运行数据库。回归测试为 `tests/test_project_images.py` 和更新后的 `tests/test_group_rank_requests.py`，并运行原有引用、排行及命令别名测试。

## 自动恢复补充

用户继续询问解决方式和是否复发后，补充了实际恢复逻辑：

- 兼容详情请求遇到连接中断、超时或 HTTP 502/503/504 时，最多尝试 3 次；每次请求超时最多 10 秒，重试共享最长 30 秒的预算，并受调用方剩余预算约束。HTTP 401/403、无效 JSON 和作品编号不匹配不会反复请求。
- 普通视频从 H.264 优先的媒体列表保留最多 3 个不重复的可信地址。首个媒体地址下载失败后，按顺序尝试备用地址，成功即停止。详情仅解析一次，下载尝试共享原下载截止时间。
- 媒体连接超时降为 10 秒、同地址重试 1 次，避免在一个故障节点上反复等待。切换地址时不续传前一个地址的文件，避免不同编码或节点的数据混入同一 MP4；媒体请求仍不带站点 Cookie。
- 实况照片沿用现有逐素材备用地址和统一转码逻辑，没有改变原作品顺序、普通图片 3 秒停留的设置。

更新后，抖音传输、下载、图片和实况相关测试共 **126 项通过**。真实链接 `x6tGqVCcCGo` 返回两个可信媒体地址；人为模拟首个媒体地址 SSL 中断后，第二个 `api.amemv.com` 地址实际下载成功。产物为 `.tmp/douyin-recovery-8f275646/douyin.mp4`，2,357,723 字节、11.028005 秒，H.264/yuv420p + AAC；原 Cookie 文件哈希未变化。

这能自动恢复部分短暂故障，但不能保证持续断网、短链始终无法取得编号、全部节点不可用或平台拒绝访问时仍然成功。本次恢复逻辑仍需重启视频 API 才生效，尚未加载到正在运行的服务；无需安装依赖。全部新增运行变更仍只有 `app/downloader.py`，验证文件为 `tests/test_douyin_transport.py`、`tests/test_downloader.py`；本次未重启、未提交、未推送、未更新笔记本。

## 15:08 再次失败后的代理证据

视频 API 已加载新的诊断代码。日志显示 `v.douyin.com` 的短链请求反复出现 `ConnectError`（连接重置）和 `ConnectTimeout`（TLS 超时）；原提取器也连接重置，兼容解析最终没有取得作品编号。问题发生在短链连接阶段，未到详情接口或媒体节点。

本机运行 Clash Verge Rev / Mihomo，启用 Meta Tunnel、fake-ip DNS、IPv6，系统 HTTP 代理开关则为关闭。系统 DNS 将 `v.douyin.com` 返回为 `198.18.0.23` 和 `fdfe:dcba:9876::2b`。关闭 Python 环境代理并不能绕过 TUN。该虚拟地址模式与 [Mihomo DNS 文档](https://wiki.metacubex.one/config/dns/) 一致。

Clash 核心日志显示抖音短链分流不一致：14:26:54、14:26:56、14:27:06、14:27:08 和 14:27:55 的 `v.douyin.com` 命中默认 MATCH，经美国节点；14:27:57 起若干请求命中 GeoIP CN，使用 DIRECT。现有 661 条规则中未发现显式抖音或 amemv 域名直连规则，最终为 `GEOIP,CN,DIRECT`、`MATCH,...`。代理还记录了多个 IPv6 网络不可达和节点超时事件。

当前只读对照：对 `d4PCQNO8rno`，系统虚拟地址请求约 1 秒返回 302；加密国内 DNS 查询到真实国内 IPv4 后，直接建立仍验证原域名证书的 TLS 连接，约 0.1 秒取得同一作品编号 `7696108173447594402`。随后运行中的视频 API 也在约 10 秒内转换成功，并清理本次诊断任务。当前已恢复不代表前述代理路径问题已修复；仅靠下载器增加重试不能修复持续失败的 TUN/代理路径。

已准备 `scripts/windows/clash-douyin-direct.js`：对 douyin.com、iesdouyin.com、amemv.com、douyinvod.com、douyinpic.com、douyinstatic.com 增加优先规则，使用独立的 `direct`、`ip-version: ipv4` 出口，并仅为上述域名设置国内加密 DNS。其他代理、分组、规则和 DNS 策略保留。此方式参照 [Mihomo direct 配置](https://github.com/MetaCubeX/Meta-Docs/blob/main/docs/config/proxies/direct.md) 和 [Clash Verge 扩展脚本文档](https://www.clashverge.dev/guide/extend.html)，通过全局脚本持久化，而非修改会被重新生成的运行配置或使用已不生效的旧版 `prepend-rules` 扩展字段。

脚本规则优先级、保留已有配置、重复执行幂等验证通过；使用当前真实配置经过脚本生成临时配置，本机 Mihomo `-t` 检查退出码 0，包含节点凭据的验证副本已立即删除。目前尚未修改用户 Clash 配置或重载代理，已请求用户授权该系统级修改。

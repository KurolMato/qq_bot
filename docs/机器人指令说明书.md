# QQ 游戏状态与视频解析机器人说明书

> 项目根目录现在只保留 `机器人管理.cmd` 作为日常入口。本文出现的登录、启动和维护脚本
> 均位于 `scripts\windows`，也可以直接在管理器菜单中选择对应功能。

本文是面向群友和机器人管理员的日常使用手册，记录当前已经实现的功能、全部群聊指令、
权限规则、运行方式和注意事项。

项目目录：

```text
E:\video_analysis
```

更详细的安装、迁移和故障排查见 [使用说明.md](使用说明.md)。

## 一、功能总览

机器人当前包含九组功能：

1. 自动识别 Bilibili、b23.tv、X、Twitter、抖音、小红书和小黑盒视频链接，转换为 MP4 后发送到群里；
2. 通过 Switch 观察账号添加 NS 好友，检测好友开始或切换游戏；
3. 读取公开的 PS4/PS5 在线状态和当前游戏；
4. 读取公开的 Steam 在线状态和当前游戏；
5. 通过微软观察账号读取公开的 Xbox 在线状态和当前游戏；
6. 从每天 04:00 开始统计本群成员的跨平台游戏时长排行榜；
7. 查看 QQ/NapCat、视频服务与各游戏平台的综合运行状态；
8. 群友共同维护游戏发售日历，自动匹配 Steam、任天堂香港与 PlayStation 香港商店资料。
9. 独立查询 HowLongToBeat 通关时长，支持中文名称解析、候选选择和持久缓存。

所有功能只在 `.env` 的 `QQ_ALLOWED_GROUPS` 所列群号中响应。多个群号使用英文逗号分隔；
留空表示监听机器人所在的所有群，不推荐。

## 二、全部群聊指令速查

Steam 全成就自动播报无需额外指令：`/steam add` 登记后自动建立基准，之后新达成全成就时发送文字及卡片。首次发现已完成的老游戏不补发，每个账号每款游戏只播报一次。卡片使用群昵称、Steam 头像、游戏封面、成就数及 Steam 累计游玩时长。正在玩的游戏约每 5 分钟检查，最近两周游戏约每 30 分钟检查；隐私不可读或网络失败仅记录日志。

在允许的群里直接 `@机器人`，如果管理员本地提供 assets/instruction.png，机器人会发送 `assets\instruction.png` 指令图片；公开源码不包含这张含第三方美术资源的图片，缺少时会返回常用指令文字；

### 游戏时长排行榜（日、周、月排行）

`/rank y` 查看上一统计日（04:00 到次日 04:00）的历史时长，`/rank o y` 查询另一成员组。
这是按已保存采样重新汇总，沿用当前昵称、成员分组和游戏屏蔽规则，并非保存当时图片；未采集到的时长不会补算。

个人时长以图片展示头像、昵称、总时长、各平台游戏及其时长，按时长降序排列；沿用排行榜卡片风格，不显示排名编号：

- `/绑定 昵称或玩家名`：绑定发送者 QQ 号，例如 `/绑定 示例玩家`；再次绑定直接替换。
- `/rank me`：查询已绑定昵称的今日时长。
- `/rank me y`、`/rank me w`、`/rank me m`：昨日、本周、本月。
- `/rank player 昵称`：查询指定成员今日时长。
- `/rank player y 昵称`、`/rank player w 昵称`、`/rank player m 昵称`：指定时间范围。

个人查询涵盖主榜和另一成员组，仍过滤屏蔽游戏。同昵称跨平台合并，支持唯一的部分昵称匹配。
`me` 依据 `/绑定` 保存的对应关系查找，不依赖最初登记者。绑定按群和 QQ 号隔离，重启后保留；昵称或平台玩家名优先精确匹配，也支持唯一的部分匹配。找不到或匹配多个成员时保留原绑定。成员改名后请重新绑定。

在群里输入 `/rank` 即可生成今日排行，输入 `/rank w` 生成本周排行，输入 `/rank m` 发送本月排行缓存图片，输入 `/rank m 8` 查看最近一次 8 月的历史月排行。日排行每天 04:00 切换；周排行从本周一 04:00 开始；月排行从当月 1 日 04:00 开始，截止时间均为生成图片时对应统计期内最后一次有效记录时间。昵称相同（忽略大小写）的 Switch、PSN、Steam 和 Xbox 记录会合并为同一名成员；成员总时长和每款游戏时长都按降序展示。`/rank remove` 和 `/rank add` 对日、周、月排行均适用，并支持忽略大小写、空格、标点的模糊匹配；例如输入 `/rank remove TBH` 即可屏蔽“TBH 塔斯巴克英雄”。

月榜（含 `/rank o m`）每天北京时间 04:00 后后台更新一次，始终发送单张图片。首次无缓存时生成，重启复用已有缓存；历史月份按需每日更新，刷新失败保留同月份旧图。图片保存在 `data/monthly_rank_cache/<群号>/<年月>/<main或other>/`。月榜只展示严格超过 1 小时的游戏，总时长和排名仍包含未展示游戏；屏蔽游戏、成员移组等修改在月榜下次刷新时体现。日榜、周榜和个人查询仍即时生成。

时长采用轮询采样累计：只有相邻两次成功样本间隔不超过 5 分钟时才计入，服务断线或电脑
关机期间不会虚增。功能部署后的第一次成功轮询只建立基线，从第二次轮询开始累计，无法
追溯部署前已经游玩的时间。数据保存在 `data\game_time.db`。

### 游戏发售日历

任何允许群的群友都可以添加游戏，所有允许群共用同一份日历：

```text
/game add 游戏官方名称
/game add switch Switch游戏官方名称
/game add psn PlayStation游戏官方名称
/game add https://ec.nintendo.com/HK/zh/titles/70010000000000
/game add https://store.playstation.com/zh-hans-hk/concept/10000000
/game list 9
/game list 2027-9
/game ol
```

不写平台前缀时默认搜索 Steam；`switch` 从任天堂香港官方目录搜索，`psn` 使用现有 PSN
登录搜索游戏，再从 PlayStation 香港商店读取官方名称、图片和发售日。也可以直接粘贴任天堂
香港或 PlayStation Store 商品链接，PS 商店直链不依赖 PSN 登录。系统自动保存官方名称、
横版游戏图和商店发售日；匹配不到游戏或商店只写了“即将推出”而没有具体日期时不会登记。
`/game list 9` 表示最近一次
到来的 9 月：月份已经过去时自动使用下一年；需要查看固定年份时输入 `/game list 2027-9`。
列表生成只读取本地 `data\game-calendar.db`，不受商店临时断网影响。

商店未收录、尚未公布具体日期或无法匹配的条目，由管理员打开后台，在“游戏发售日历管理”
中手动填写名称、选择平台和发售日期并上传封面，再拖动、缩放蓝色选区确定最终横版取景。后台也可以查看、
修改和删除所有已添加游戏；保存后群内 `/game list 月份` 立即使用新资料，无需重启机器人。
机器人会在每天设定时间之后，把“明日发售”和“今日发售”的游戏分别合成日历卡片，自动发送到 `QQ_ALLOWED_GROUPS` 中的每个群。每个群、每个发售日和提醒批次只发送一次，重启机器人不会重复提醒。可在管理后台修改提醒小时、提前天数和检查间隔；默认配置为 09:00，提前 1 天及发售当天提醒。
`/game ol` 只读取当前群四个平台最后一次轮询保存的状态，按照 Steam、PS、Switch、Xbox
从左到右排列；没有在游戏中的登记不会出现在图片里。

## 三、Bilibili、X、抖音、小红书与小黑盒视频解析

### 使用方法

不需要输入指令，直接在允许的群里发送链接或使用手机分享卡片。例如：

```text
https://www.bilibili.com/video/BVxxxxxxxxxx
https://b23.tv/xxxxxxx
https://x.com/用户名/status/数字
https://twitter.com/用户名/status/数字
https://v.douyin.com/短链/
https://www.douyin.com/video/数字
https://xhslink.cn/o/分享码
https://xhslink.com/a/分享码
https://www.xiaohongshu.com/explore/笔记ID
https://api.xiaoheihe.cn/v3/bbs/app/api/web/share?...&link_id=分享码
```

机器人识别后在后台下载、合并或重封装为 MP4，完成后直接发送视频，不发送“检测到链接，
正在转换”之类的开始提示。

### 规则和限制

- 支持普通文本，以及 OneBot JSON/XML/share 手机分享卡片中的链接；
- 每条消息只处理发现的第一个受支持链接；
- 同一群、同一链接在五分钟内去重；不同群同时提交同一链接时共享一次转换并分别投递；
- Bilibili 使用 yutto，X/Twitter、抖音、小红书与小黑盒使用 yt-dlp，最终通过 FFmpeg 输出 MP4；
- 默认群文件上限由 `QQ_MAX_VIDEO_MB` 控制，当前模板默认 100 MB；
- 超时、文件过大、动态没有视频等明确情况保持静默，不会在群里刷失败消息；
- 私密、付费、地区限制或需要登录的内容不会绕过平台访问控制；
- X 受限内容可由管理员合法配置 Cookie，Cookie 不得发送到群里。
- 抖音公开短链默认无需登录；触发风控时可配置专用 Cookie，Cookie 不得发送到群里。
- 小红书只处理视频笔记，图文笔记保持静默；触发登录风控时可在管理后台配置专用 Cookie。

网页与转换 API 是同一个进程。可以关闭浏览器标签，但 `Video MP4 Web API` 窗口必须保持
运行，否则群聊视频转换不可用。

## 四、Switch 视奸功能

### 首次准备

管理员需要在机器人电脑上打开 `机器人管理.cmd`，选择 `7`。

按照窗口提示完成 Nintendo 登录。只有终端出现 `Login and verification succeeded` 才算成功。
回调地址和 session token 属于敏感登录信息，不得发送到 QQ、截图或公开仓库。

### 添加好友码

```text
/switch add SW-1111-2222-3333
/switch add SW-1111-2222-3333 群友小明
```

机器人会依次执行：

1. 查询好友码对应的 Nintendo 账号；
2. 检查观察账号是否已经与对方成为好友；
3. 尚未成为好友时，发送真实的 Nintendo Switch 好友申请；
4. 保存好友码、NSA ID、昵称、头像、发起者 QQ 和当前群号；
5. 对方同意后自动进入“视奸中”；
6. 开始或切换游戏时向登记群发送活动卡片。

“正在发送好友申请…”，成功结果和所有错误提示都会引用回复原始 `/switch add` 消息，
方便多人同时操作时区分结果。

只读查询遇到 `fetch failed`、`ECONNRESET`、TLS 断开或 502/503/504 时，会按 2 秒、
5 秒的间隔自动重试两次。发送好友申请属于外部写操作，不会盲目自动重试。

### 查看列表

```text
/switch list
```

示例：

```text
示例玩家｜视奸中｜未在游戏
小明｜视奸中｜Mario Kart World
```

列表只显示昵称（未设置时显示平台名称）、“视奸中”和游戏名，不显示账号 ID 或登记者 QQ。
列表只读取本地 SQLite，不等待 nxapi 网络请求。

已有记录可设置昵称：`/switch nickname 好友码 昵称`。

### 删除记录

```text
/switch remove SW-1111-2222-3333
```

删除规则：

- 只有最初登记这条记录的 QQ 用户可以删除；
- 群主和管理员不能删除其他人的登记；
- 每位 QQ 用户可以登记多个好友码，也可以代其他人添加；
- 删除登记不会自动解除 Nintendo 好友关系；
- 如需解除好友，请在 Switch 上手动操作。

### 检查状态

```text
/switch status
```

成功时显示观察账号当前的 Switch 好友数量。该命令会真实请求 nxapi/Nintendo；外部服务
故障时可能显示“nxapi 尚未就绪”，这不一定代表登录失效。先查看：

<https://nxapi-status.fancy.org.uk/>

只有明确提示登录失效时才需要重新运行 `switch-login.cmd`。

### 多群规则

同一个好友码可以登记到多个群。本地已知该账号时，新群直接复用 NSA ID、昵称和头像，
不会重复发送好友申请；活动卡会发送到所有登记过他的群。新群第一次轮询时如果对方正在
游戏，会立即给新群补发当前状态卡。

## 五、PS4/PS5 视奸功能

### 首次准备

管理员需要准备一个 PSN 观察账号，并打开 `机器人管理.cmd`，选择 `8`。

先在浏览器登录该 PSN 账号，再打开：

<https://ca.account.sony.com/api/v1/ssocookie>

只把 JSON 中 `npsso` 引号内的 64 位字符串粘贴进登录脚本。NPSSO 等同登录凭据，不得
发送到 QQ、截图、文档或公开仓库。凭据默认保存在 `secrets\psn-npsso.txt`。

### 添加 PSN 玩家

```text
/psn add Player-One
/psn add Player-One 群友小明
```

PSN 在线 ID 必须为 3～16 位字母、数字、下划线或连字符，并以字母开头。

PS5 功能会直接读取目标玩家公开的 Presence：

- 读取成功后才保存到本群视奸列表。

如果隐私设置不允许读取，机器人会 @ 指令发送者并提示：

```text
请把“在线状态和当前游戏”设为所有人可见
```

目标玩家需要在 PlayStation 隐私设置中把“在线状态和当前游戏”的可见范围改为“所有人”，
然后重新执行 `/psn add PSN在线ID`。

### 查看列表

```text
/psn list
```

列表只显示昵称（未设置时显示 PSN 在线 ID）、“视奸中”和游戏名。该命令只读取本地数据库，
不会等待 PSN 网络查询。已有记录可用 `/psn nickname PSN在线ID 昵称` 改名。

### 删除记录

```text
/psn remove Player-One
```

只有最初登记这条记录的 QQ 用户可以删除；群主和管理员不能删除其他人的记录。每位 QQ
用户可以登记多个 PSN 玩家。同一玩家可以登记到多个群，活动卡会发送到所有登记群。

### 检查状态

```text
/psn status
```

正常时只回复：

```text
PS5 服务正常。
```

不会显示观察账号的 PSN 在线 ID。如果提示尚未登录，管理员运行 `ps5-login.cmd` 后重启
`Video QQ Bot`。

## 六、Steam 视奸功能

Steam 不需要观察账号添加好友，但管理员必须先运行 `steam-login.cmd` 配置 Steam Web API
Key。目标玩家需要公开“我的个人资料”和“游戏详情”。

支持三种登记方式：

```text
/steam add 76561198000000000
/steam add 39734272
/steam add https://steamcommunity.com/id/自定义ID
/steam add 自定义ID
/steam add 自定义ID 群友小明
```

查看、删除和检查服务：

```text
/steam list
/steam remove 76561198000000000
/steam status
/steam nickname SteamID64或名称 群友小明
```

机器人检测到玩家开始或切换游戏时，会发送头像、Steam 游戏封面、玩家名称和游戏名称卡片。
游戏名称优先显示 Steam 商店官方简体中文，未提供中文时保留原名。
群内成员可以删除本群登记，不会影响其他群。需要竖版 Steam 封面时，管理员运行
`steamgriddb-login.cmd` 配置可选的 SteamGridDB API Key。

## 七、游戏活动卡片

Switch、PlayStation、Steam 和 Xbox 使用同一套 640×220 深色卡片，内容包括：

- 左侧竖版游戏封面；
- 玩家头像；
- 绿色“正在游玩”状态；
- 玩家昵称或 PSN 在线 ID；
- 当前游戏名称；
- 平台胶囊。

平台胶囊规则：

- Switch：红底 `Switch`；
- PlayStation：蓝底 `PS`。
- Steam：蓝底 `Steam`。
- Xbox：绿底 `Xbox`。

### Xbox 首次配置与指令

管理员打开项目管理后台，点击顶部“打开 Xbox 登录”，在浏览器用观察账号完成一次微软登录，
然后重启 QQ Bot。该方案不需要 OpenXBL 手机号验证、API Key、Azure 应用或 Client Secret。
机器人只读取目标玩家允许公开访问的在线状态。

```text
/xbox add ExampleXboxPlayer
/xbox add ExampleXboxPlayer 小明
/xbox list
/xbox nickname ExampleXboxPlayer 新昵称
/xbox remove ExampleXboxPlayer
/xbox status
```

Xbox 指令的参数直接使用空格分隔，不再使用英文竖线。如果无法读取目标状态，目标玩家需要
把 Xbox 隐私中的在线状态、当前游戏和游戏历史可见范围设为“所有人”。

卡片不会显示累计游玩时间、在线人数、今日能力等统计信息。默认只在开始游戏或切换游戏
时发送；停止游戏和离线只重置内部状态，不发送通知。

PSN Presence 没有直接提供封面时，机器人根据 `npTitleId` 从 PlayStation 游戏目录补查
竖版封面并缓存。图片 CDN 暂时不可用时，卡片仍会生成，但对应位置可能显示占位色。

## 八、机器人综合状态

```text
/bot status
```

示例：

```text
机器人运行状态：
QQ / NapCat：正常（已连接）
视频解析：正常（正常）
Switch：正常（正常）
PS5：正常（正常）
Steam：正常（正常）
Xbox：正常（正常）
运行时间：2小时15分钟
```

该命令只读取本地保存的最近健康状态，不会临时请求 Nintendo、PlayStation、Steam、Xbox 或视频接口，
所以外部服务卡顿时也能快速回复。启动后前 30 秒内部分项目可能显示“启动中”。

## 九、登记权限和隐私规则

- 机器人只响应 `QQ_ALLOWED_GROUPS` 中的群；
- 群成员可以添加多个 Switch 好友码、PSN 玩家和 Steam 玩家；
- 不限制只能给自己登记，可以代其他人添加；
- 只有原始登记者可以删除自己的记录；
- 群主和管理员没有删除其他人记录的额外权限；
- `/switch list`、`/psn list` 和 `/steam list` 使用精简纯文本，不显示账号 ID 或登记者 QQ；
- 同一个群友昵称可以同时绑定 Switch、PSN 和 Steam，不要求昵称唯一；
- 同群任何成员都可以修改已有记录的昵称；删除记录仍然只有原始登记者可以操作；
- 群里不会显示 nxapi/PSN 原始接口响应、程序堆栈、本机路径或登录凭据；
- Switch 好友申请是真实外部操作，应确保好友码由本人自愿提供；
- 不要批量骚扰陌生好友码。

## 十、日常启动

双击项目根目录中的 `机器人管理.cmd`，输入 `1` 启动整套机器人。也可以在 PowerShell 中运行：

```powershell
cd E:\video_analysis
.\机器人管理.cmd
```

管理器会调用 `scripts\windows\start-all.cmd`，依次：

1. 检查并按需启动 NapCat 和 QQ；
2. 启动 `Video MP4 Web API`；
3. 启动 `Video QQ Bot`；
4. 检查 `http://127.0.0.1:8000/health`；
5. 检查 QQ Bot 是否监听 `127.0.0.1:8081`；
6. 已经运行的组件不会重复启动。

正常运行时只显示并需要保留 `Video QQ Bot` 窗口。NapCat、视频 API 和看门狗在后台运行，
相关输出分别写入 `data\napcat-launch.log`、`data\video-api.log` 和管理后台日志。

根目录入口不受 PowerShell ExecutionPolicy 限制，不需要修改系统脚本执行策略。

## 十一、日常关闭和重启

只重启 QQ Bot：

1. 在 `Video QQ Bot` 窗口按 `Ctrl+C`；
2. 等程序结束后关闭窗口；
3. 打开 `机器人管理.cmd`，选择 `1`。

完全关闭：打开 `机器人管理.cmd`，选择 `2`。脚本会先停止看门狗，再关闭 QQ Bot、视频 API 和 NapCat；如托盘仍有普通 QQ 客户端，再从系统托盘正常退出。

不要直接结束所有 `python.exe`，电脑上可能还有其他 Python 程序。视频下载过程中关闭 API
会立即中断当前任务。

## 十二、长期运行与自动恢复

机器人为后台任务提供以下稳定性机制：

- Switch、PS5、Steam、直接 Presence 和健康检查任务异常退出后自动拉起；
- Switch 连续失败最长退避 10 分钟；
- PS5 连续失败最长退避 15 分钟；
- Steam 连续失败最长退避 15 分钟；
- Xbox 连续失败最长退避 15 分钟；
- 视频 API 健康检查连续失败最长退避 5 分钟；
- 同类持续错误最多每 5 分钟写一次日志；
- 任意一次成功后立即恢复正常轮询频率；
- Switch、PS5、Steam 与 Xbox 使用独立后台任务和 SQLite WAL 数据库；
- Xbox 刷新令牌使用跨进程锁并立即安全落盘，避免登录窗口与机器人同时刷新；
- PSN 同步网络请求使用独立线程，不阻塞本地列表命令。
- QQ Bot 每 5 秒写入应用层 OneBot 心跳；连续断开时外部看门狗先重启 QQ Bot，仍未恢复再
  重启 NapCat，不以瞬间出现的 TCP 连接作为恢复依据；
- Python 标准日志、NoneBot 日志统一写入 UTF-8 的 `data\qq-bot.log`，平台和下载模块异常可在后台查看，群聊 Emoji 不再触发 GBK 日志编码错误。

这些机制可以恢复程序内部任务、QQ Bot 意外退出和 WebSocket 假连接，但电脑关机、休眠、
断电或看门狗本身被关闭后仍需打开 `机器人管理.cmd`，选择 `1` 重新启动。

## 十三、常见提示说明

### `nxapi 尚未就绪：Switch 服务暂时无法完成操作`

通常是 nxapi 的解密、认证或 Nintendo 接口临时异常，不一定是登录失效。等待自动重试，
并查看 nxapi 状态页。不要因为一次 502、fetch failed 或 ECONNRESET 就重新登录。

### `PSN 观察账号尚未登录`

在机器人电脑运行 `ps5-login.cmd`，粘贴新的 NPSSO，登录成功后重启 QQ Bot。

### `请把“在线状态和当前游戏”设为所有人可见`

目标 PSN 玩家隐私设置不允许公开读取。由目标玩家修改隐私设置后重新执行 `/psn add`。

### `Steam Web API Key 尚未配置`

在机器人电脑运行 `steam-login.cmd`，从 Steam 官方 API Key 页面获取并保存 Key，然后重启 QQ Bot。

### `请把 Steam“我的个人资料”和“游戏详情”设为公开`

目标 Steam 玩家需要修改个人资料隐私设置，然后重新执行 `/steam add`。

### `/switch list`、`/psn list` 或 `/steam list` 没有回复

先执行 `/bot status`，再检查：

1. `Video QQ Bot` 窗口是否仍运行；
2. NapCat 是否已连接 `ws://127.0.0.1:8081/onebot/v11/ws`；
3. 当前群是否在 `.env` 的 `QQ_ALLOWED_GROUPS` 中；
4. 终端是否出现 `Switch list sent`、`PS5 list sent` 或 `Steam list sent`。

### 视频链接没有反应

确认链接域名和格式受支持，检查 `Video MP4 Web API` 是否运行，并访问：

<http://127.0.0.1:8000/health>

正常结果应为：

```json
{"status":"ok"}
```

## 十四、重要文件位置

| 文件或目录 | 用途 |
|---|---|
| `机器人管理.cmd` | 根目录唯一日常入口，包含启动、停止、登录、更新和日志菜单 |
| `scripts\windows\start-all.cmd` | 一键启动 NapCat、视频 API 和 QQ Bot |
| `scripts\windows\switch-login.cmd` | 登录 Nintendo Switch 观察账号 |
| `scripts\windows\ps5-login.cmd` | 登录 PSN 观察账号 |
| `scripts\windows\steam-login.cmd` | 保存并验证 Steam Web API Key |
| `scripts\windows\steamgriddb-login.cmd` | 保存并验证可选的 SteamGridDB 竖版封面 API Key |
| `.env` | 当前电脑实际配置，不应公开 |
| `.env.example` | 无敏感信息的配置模板 |
| `data\switch_registry.db` | Switch 好友码登记、昵称和最近状态 |
| `data\game-calendar.db` | 全群共享的游戏发售日历 |
| `data\game-calendar-images\` | 后台上传并裁剪后的本地游戏封面 |
| `data\game_time.db` | 日、周、月排行榜的历史采样数据与屏蔽规则 |
| `data\monthly_rank_cache\` | 按群、月份、成员组和统计日保存的月榜图片缓存 |
| `secrets\` | 登录凭据目录，不应公开或发群 |
| `downloads\` | 视频任务临时目录；投递成功后延迟清理 |
| `qq_bot\` | QQ Bot 源代码 |
| `app\` | 网页和视频转换 API 源代码 |

迁移电脑时至少备份 `.env`、三个 `data\*.db` 数据库和必要的 `secrets\` 凭据。凭据备份
必须放在可信的私有存储中，不要提交到 Git 或上传公开网盘。

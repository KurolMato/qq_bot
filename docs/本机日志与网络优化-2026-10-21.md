# 本机日志与网络优化（2026-10-21）

排查范围：本机保留的 QQ Bot 日志（主要为 10 月 20 日 14:23 至 21 日 10:01，约 20 小时）、视频 API 历史日志、NapCat 看门狗和 Clash 连接日志。历史 API/NapCat 输出有些没有逐行时间，不能把这些累计记录全部当成今天的故障。

## 已确认的问题

| 现象 | 证据及判断 |
| --- | --- |
| Steam 成就重复返回 403 | 查询失败记录中有 580 次玩家成就 HTTP 403，且监控层又各写一条日志。403 本身不能证明 API Key 失效或确定是隐私限制，原来固定每 10 分钟再次查询会持续产生无效请求。 |
| Steam 线路不稳定 | hosts 中存在 Steam Community 302 写入的 `127.0.0.1 api.steampowered.com`。同一公共接口，系统 TUN 路径出现 ConnectError，本机显式代理返回 HTTP 200。此结果证实本机访问路径有差异，不能据此把全部成就 403 归因于 hosts。 |
| PSN 奖杯反复重扫 | 111 条 TrophyChanged、19 条 ValueError 延后日志；只读数据库检查发现部分账号已同步可见游戏，但可见游戏总数与账号奖杯总数不一致，另有账号卡在详情校验。不能用不完整的数据建立完整基线。 |
| 图片下载偶发全失败 | 小黑盒有 3 次全部图片失败；图片域名 `imgheybox1.max-c.com` 的 Clash 记录在直连与美国节点间切换，出现连接超时。只读复查历史帖子返回 7 张图片，真实图片请求返回 HTTP 206、图片 MIME，说明复查时可用，不能判定持续宕机。 |
| 视频下载其他失败 | 抖音有短链接/详情连接失败，B 站有媒体连接失败；另有 3 个视频超过现有 100 MB 发送上限。超限属于既定限制，增加网络重试不能解决。 |
| 日志保留不足 | 原来记录每条普通消息的 DEBUG 匹配细节，2 MB 轮转、仅保留 3 份，故障现场很快被覆盖。 |

看门狗近期存在心跳过期后自动拉起机器人的记录，随后恢复稳定；历史 NapCat 的重复登录/版本偏移提示不能等同于当前 QQ 掉线。本次没有升级 QQ/NapCat，也没有手动重启服务。

## 本次实现

- Steam 新增 `STEAM_HTTP_PROXY`，管理台可编辑。设置后 Web API 使用指定 HTTP/HTTPS 代理；留空保留原来的自动线路策略。不会因此改动系统 hosts、系统代理或 Clash 全局规则。
- 本机 `.env` 仅追加 `STEAM_HTTP_PROXY=http://127.0.0.1:7897`，其余已有字节保持不变。端口来自本机 Clash 实际配置，且已用新客户端和保存后的配置验证公共 API 成功，耗时约 0.84 秒。此设置需要 Clash 持续运行；端口改变时在管理台更新。
- Steam 每次 API 尝试限制为 8 秒（连接超时 4 秒），最多 3 次并退避，给外层 30 秒成就工作时限留出恢复机会。原来单次 35 秒会在首次超时之前就被外层取消。403 等非暂时性响应不立即重试。
- 玩家成就连续不可读时，持久化保护间隔依次为 10、20、40、60 分钟，上限 1 小时；活跃游戏不会缩短失败冷却，成功后恢复原有频率。成就通知可能随访问恢复及冷却延后，并非保证立即恢复。底层重复的预期状态日志降为 DEBUG，监控层仍记录状态及下一次重试时间。
- PSN 数据校验失败先保持短间隔重试；累计失败达到 4 次时延后 12 小时，网络异常仍最多退避 1 小时。保留既有成功基线与已同步详情，不把缺失数据算成零。日志补充本地校验原因、可见/账号总数和重试间隔。
- 抖音、小红书、小黑盒和 B 站共用的静态图文下载入口，对连接中断、读超时、408/429/500/502/503/504 最多尝试 3 次。各图片共享作品总时限，中断图片从头下载；403、404、无效地址、图片解码失败和本地文件错误不重试。顺序和原有部分图片成功的处理方式保持一致。失败记录只含平台、图片序号、域名及异常类型/HTTP 状态，不输出带签名的地址。
- 可预期的转换失败记录为 WARNING，不再附一整段调用栈；未知程序异常仍保留异常日志。
- QQ Bot 文件日志改为 INFO 起、5 MB 轮转、保留 7 份轮转文件；文件异常日志关闭局部变量展开。共享退避计算避免长期断网造成指数溢出。

## 验证与生效

覆盖下载、图文、实况、视频 API、QQ 发送模拟、Steam/PSN/Switch/Xbox 轮询、共享退避和后台配置共 463 项测试。扩大回归首次 460 项通过，3 个旧测试因本机缺少 pytest-asyncio 未运行；改为项目常用的 `asyncio.run` 后，补跑包含这 3 项及后台配置的 25 项全部通过（与前述测试重叠，不累加）。无需新增运行依赖。只读网络验证未向任何真实群发送测试消息，未覆盖运行数据库或登录凭据。

通过 `机器人管理.cmd` 重启视频 API 和 QQ Bot 后，全部代码与配置才会生效。本次没有统一重启；检查时运行日志仍显示旧 Steam 查询行号及 DEBUG 文件记录，因此不能认为运行进程已经加载全部优化。

本机代码和配置已完成，未提交、未推送，笔记本未更新。平台验证码、权限限制及外部线路故障仍可能发生，本次优化提供有限重试、较合理的冷却与可定位的日志，不保证平台永不报错。

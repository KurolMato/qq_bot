# 小黑盒图文发送

10 月 18 日新增标题发送：少量图片与标题文字同发，多图聊天记录以标题文字节点开头。实现、同步文件与验证见 `图文标题发送-2026-10-18.md`。

## 行为

- 帖子图片不超过 5 张：直接发送一条图片消息。
- 帖子图片超过 5 张：发送一条合并聊天记录，每张图片一个节点，保持原顺序。节点使用机器人自己的 QQ 号，显示名为“小黑盒图文”。
- 视频帖子保留视频发送行为，不另发视频封面；纯文字帖保持静默。
- 只提取帖子自身的图片列表或正文图片，不提取作者头像或评论图片。相同图片地址去重。
- 图片发送后沿用现有共享任务、跨群复用和延迟清理流程；发送失败会释放去重记录，允许重试。个别图片下载失败时保留其他成功图片的相对顺序，在任务日志中记录失败位置；发送方式按实际成功图片数量选择。

## 实现与依赖

全部运行变更文件：

- `app/downloader.py`：识别小黑盒详情中的图片列表和 HTML 正文图片；按顺序下载图片，复用现有图片格式处理与 API 图片任务。图片请求限定小黑盒 `max-c.com` CDN，逐次检查重定向，并共享图文下载时间预算。
- `qq_bot/plugin.py`：仅对小黑盒超过 5 张的图片任务调用 `send_group_forward_msg`；其他平台的发送规则继续使用原逻辑。

依赖沿用现有 HTTPX、Pillow 和 OneBot/NapCat，无需新增安装。图片任务不调用 yt-dlp 或 FFmpeg。

参考：小黑盒详情字段参照解析客户端的[字段处理代码](https://github.com/advent259141/astrbot_plugin_xiaoheihe_adapter/blob/main/xhh_client.py)；聊天记录节点参照 [NapCat 消息格式文档](https://napneko.github.io/develop/msg)，并使用本机 OneBot 适配器的 `MessageSegment.node_custom`。

## 20:31 失败排查与会话支持

失败任务 `33c3c67bbb9847b9a7c7a382b6471f43` 对应帖子 `b1a672a6e9d3`。只读复查接口返回 HTTP 200、业务状态 `show_captcha`，没有作品详情。这不是图片下载或聊天记录发送阶段的错误；旧代码将所有非 `ok` 状态统一替换为“暂时无法解析该帖子”，丢失了可操作的原因。Clash 当时的记录确认 `api.xiaoheihe.cn` 走 DIRECT，不能沿用此前抖音的代理分流结论。

用户一度反馈浏览器里该帖子打不开。随后使用用户给出的完整分享链接打开页面，页面显示验证成功后正常加载，标题为“小天才职业摄影师”，包含 7 张图片，证实该帖子并未删除。后台接口随即返回 `ok`。没有自动完成或破解验证码。

本次补充：

- `show_captcha` 明确提示在浏览器手动验证，`login`、`relogin`、`lack_token` 明确提示登录状态问题。验证码不作自动重试，不提交或破解验证码。
- 支持可选 `XIAOHEIHE_COOKIES_FILE`，可以在管理后台设置 Netscape 格式 Cookie 文件路径。Cookie 仅用于详情请求，排除过期与其他域名的数据，不发送给图片 CDN，不改写原文件。
- 配置 Cookie 只是复用用户合法会话，不保证解除验证码；匿名公开图文仍默认不需要配置。需要登录时先在浏览器确认作品可访问、手动完成验证，再将导出的 Cookie 保存到本机，并在后台填写路径后重启视频 API。

本次补充的全部运行与配置文件为 `app/downloader.py`、`app/admin.py`、`static/admin.html`、`.env.example`；验证文件为 `tests/test_xiaoheihe_images.py`。连同本次图文功能整体同步时，还需此前的 `qq_bot/plugin.py`，并沿用目标机器已有的通用图片任务文件。

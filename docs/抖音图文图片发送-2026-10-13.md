# 抖音图文直接发送图片

本文件记录 10 月 13 日版本。10 月 14 日已新增抖音和小红书实况 MP4 支持，当前行为见 `docs/实况图文转MP4-2026-10-14.md`。

2026-10-13 本机实现完成。普通视频继续发送 MP4；抖音图文按作品图片顺序发送，每条 QQ 消息最多 10 张。图片不合成视频，不下载配乐，不裁切或添加背景。JPEG、PNG、GIF 保留原文件；其他 Pillow 可读取的格式转为原尺寸 JPEG。

任务 API 新增 `media_type`、`image_urls`，图片通过带访问检查的 `/api/jobs/{id}/images/{index}` 提供。图片任务沿用共享任务、发送后延迟清理和终态任务过期清理。网页也能下载图片结果。

图文优先使用普通视频已有的兼容详情请求；该请求失败时使用原有 f2 专用环境兜底。f2 补充小写 `x-tt-argus` 请求头，并忽略已过期 Cookie。f2 输出中的完整签名 URL 不再透传到任务错误或机器人日志。

此前只读复查中，用户提供的作品 `7695794821420975973` 未带 Argus 请求头时返回 403，带请求头后返回 HTTP 200，但没有返回作品详情。HTTP 200 不等于作品可下载；不能声称这条具体作品已恢复。作品本身的访问限制或接口风控仍可能造成失败。

## 验证与生效

使用 `tools/select_python.cmd` 选择的本机 Python，129 项针对性测试通过：图片下载、顺序与原尺寸保持、格式兼容、任务 Cookie 清理、错误信息脱敏、图片 API 的访问检查/删除、QQ 图片分批发送，以及普通视频回归。测试采用临时数据与模拟接口，没有向真实群发送测试消息。

需要重启视频 API 和 QQ Bot 才能生效，可通过 `机器人管理.cmd` 操作。已有环境无需新增依赖，保留现有 f2 专用环境作为备用解析组件。本次未重启运行进程、未提交、未推送，笔记本尚未更新。

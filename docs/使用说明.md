## 一、先理解两个后台程序

本项目运行时包含两个服务：

| 服务 | 端口 | 用途 | QQ 机器人运行时能否停止 |
|---|---:|---|---|
| `Video MP4 Web API` | 8000 | 下载 B 站、X、抖音、小红书或小黑盒内容、合并 MP4，并提供内部 API 和可选网页 | 不能 |
| `Video QQ Bot` | 8081 | 接收 NapCat 上报的群消息，并把 MP4 发回群里 | 不能 |

网页和转换 API 是同一个进程。你可以关闭浏览器页面、不使用网页，但不能停止 8000 端口的 API，否则 QQ 机器人虽然能看见群消息，却无法转换视频。

两个服务都只绑定 `127.0.0.1`，默认只能由本机访问，不会直接开放到局域网或公网。

## 二、日常启动方法

### 推荐：一键启动

打开 PowerShell 或命令提示符：

双击项目根目录的 `机器人管理.cmd`，选择“启动整套机器人”。需要在终端直接运行时使用
`scripts\windows\start-all.cmd`。

该命令现在会依次完成：

1. 检查 NapCat 是否已经运行；
2. 如果没有运行，通过 `D:\NapCat.Shell\launcher-win10.bat` 启动 NapCat 和 QQ；
3. 启动 `Video MP4 Web API`；
4. 启动 `Video QQ Bot`。

首次启动 NapCat 时 Windows 可能弹出管理员权限确认，请点击“是”。启动完成后只保留 `Video QQ Bot` 窗口；NapCat、视频 API 和看门狗在后台运行。NapCat 和 API 输出分别保存在 `data\napcat-launch.log`、`data\video-api.log`，机器人行为和异常可在管理后台查看。根目录管理入口不受 PowerShell ExecutionPolicy 限制。

脚本会避免重复启动：如果 `NapCatWinBootMain.exe` 已经存在，或 8000/8081 端口已经监听，就跳过对应程序。

NapCat 启动器路径配置在 `.env`：

```dotenv
NAPCAT_LAUNCHER=D:\NapCat.Shell\launcher-win10.bat
NAPCAT_QQ=100000001
```

以后移动 NapCat 文件夹时，只需修改 `NAPCAT_LAUNCHER`。`NAPCAT_QQ` 是快速登录使用的 QQ 号；留空时 NapCat 会使用普通登录流程。

当前 NapCat 版本实际识别的命令行格式是：

```bat
D:\NapCat.Shell\launcher-win10.bat -q 100000001
```

`-q` 代表快速登录，后面跟 QQ 号。部分旧说明写成 `launcher-win10.bat 123456`，但当前程序源码只解析 `-q`/`--qq`，因此本项目使用带 `-q` 的格式。

### 判断启动是否成功

API 窗口应出现：

```text
Uvicorn running on http://127.0.0.1:8000
```

QQ Bot 窗口应出现类似：

```text
Succeeded to load plugin "plugin" from "qq_bot.plugin"
Loaded adapters: OneBot V11
Uvicorn running on http://127.0.0.1:8081
```

NapCat 日志不再出现 `ECONNREFUSED 127.0.0.1:8081`，并显示 WebSocket 已连接，即表示机器人接入成功。NapCat 最多可能要等 30 秒才自动重连。

### 网页是否需要打开

不需要。网页只是可选操作界面。机器人运行时可以不打开任何浏览器。

需要临时查看网页时访问：

<http://127.0.0.1:8000>

看完直接关闭浏览器标签即可，不会影响机器人。

## 三、关闭方法

### 完全关闭机器人系统

打开 `机器人管理.cmd` 并选择 `2`，即可停止 QQ Bot、视频 API、项目看门狗和由本项目启动的 NapCat 进程。脚本会先停止看门狗以避免机器人被重新拉起；如 QQ 托盘仍有普通客户端，再从托盘正常退出。

停止 QQ Bot 后，NapCat 出现 WebSocket 断开或 `ECONNREFUSED` 是正常现象。NapCat 会定期重连，但不会影响 QQ 本身正常使用。

如果机器人正在下载视频，关闭 API 窗口会立即中断该任务。

### 只暂停群机器人

只在 `Video QQ Bot` 窗口按 `Ctrl+C`，保留 API 窗口。

效果：

- 群里的 B 站和 X 链接不再触发机器人；
- 网页和转换 API 仍可使用；
- NapCat 会报告 WebSocket 断开，这是正常的。

### 只关闭网页界面可以吗

网页没有独立进程。关闭浏览器标签即可达到“不使用网页”的效果。

不要为了关闭网页而停止 `Video MP4 Web API` 窗口，因为 QQ Bot 也依赖这个进程。

### 窗口找不到时强制关闭

先查询占用端口的进程：

```powershell
Get-NetTCPConnection -State Listen | Where-Object LocalPort -in 8000,8081 |
  Select-Object LocalAddress,LocalPort,OwningProcess
```

确认 PID 后关闭指定进程：

```powershell
Stop-Process -Id 这里填写PID
```

不要直接结束所有 `python.exe`，电脑上可能还有其他 Python 程序。

## 四、分别启动某个程序

需要观察错误日志时，建议在两个 PowerShell 窗口中分别启动。

### 启动转换 API

```powershell
cd E:\video_analysis
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

### 启动 QQ Bot

```powershell
cd E:\video_analysis

```

QQ Bot 启动前应先启动转换 API。

## 五、NapCat 配置

NapCat WebUI 默认地址通常为：

<http://127.0.0.1:6099/webui/>

实际端口和登录 token 以 NapCat 启动日志或 `webui.json` 为准。不要把 token 发送给其他人；如果泄露应立即修改并重启 NapCat。

在 NapCat WebUI 中配置：

1. 打开 OneBot 11 网络配置；
2. 新增或启用 `WebSocket 客户端/反向 WebSocket`；
3. URL 填写 `ws://127.0.0.1:8081/onebot/v11/ws`；
4. 消息格式选择 `array`；
5. 保存配置并等待自动重连。

NapCat 与本项目在同一台 Windows 电脑上时，必须使用上述 `127.0.0.1` 地址。

## 六、机器人如何工作

在允许的 QQ 群中发送以下任意内容：

- `https://www.bilibili.com/video/BV...` 完整链接；
- 手机 B 站分享产生的“标题 + `https://b23.tv/...`”文案；
- X/Twitter 的 `https://x.com/用户/status/数字` 推文链接；
- 抖音的 `https://v.douyin.com/短链/` 或 `https://www.douyin.com/video/数字` 链接；
- 小红书的 `https://xhslink.cn/类型/分享码`、`https://xhslink.com/类型/分享码` 或 `https://www.xiaohongshu.com/explore/笔记ID` 链接；
- 小黑盒的 `https://api.xiaoheihe.cn/v3/bbs/app/api/web/share?...&link_id=...` 分享链接；
- 常见的 B 站、X、抖音、小红书或小黑盒 JSON、XML、分享卡片。

机器人会：

1. 检测消息中的第一个 B 站、X/Twitter、抖音、小红书或小黑盒链接；
2. 调用本机 8000 端口的转换 API；
3. 下载视频并使用 FFmpeg 合并为 MP4；
4. 转换完成后通过 NapCat 直接把视频发回原群，中途不发送提示。

同一群的同一链接五分钟内不会重复处理；不同群同时发送同一链接时只转换一次，再分别发往各群。默认超过 100 MB 的视频不会尝试发送。视频发送成功后默认延迟 180 秒清理本地文件，避免 NapCat 读取文件时被提前删除；超时、文件过大、动态没有视频等明确情况不在群里发送失败提示。

### X 登录限制与 Cookie（可选）

公开推文默认走 yt-dlp 的匿名 Twitter syndication 接口，不需要登录。年龄限制、仅关注者、
敏感内容或 X 要求登录的推文可能需要 Cookie。可在 `.env` 二选一配置：

```dotenv
# 推荐：单独导出的 Netscape cookies.txt，绝对不要提交到 Git 或发进群
X_COOKIES_FILE=E:\video_analysis\secrets\x-cookies.txt

# 或读取本机浏览器登录态，例如 edge、chrome、chrome:Default
X_COOKIES_FROM_BROWSER=
```

两项都为空时使用匿名模式；两项都填写时优先 `X_COOKIES_FILE`。浏览器 Cookie 等同账号凭据，
建议使用专门的 X 账号，并确保 Cookie 文件不进入项目版本库。

抖音公开视频默认匿名解析。如果日志提示需要登录或触发风控，可在 `.env` 中配置
`DOUYIN_COOKIES_FILE` 或 `DOUYIN_COOKIES_FROM_BROWSER`，规则与 X Cookie 相同。

小红书视频笔记同样优先匿名解析，图文笔记不会触发失败回复。若触发验证码或登录风控，可在
管理后台填写“小红书浏览器 Cookie”为 `edge` 或 `chrome:Default`；填写前先在对应浏览器登录
小红书。也可配置 `XIAOHONGSHU_COOKIES_FILE` 使用单独导出的 Netscape Cookie 文件。

## 七、修改群白名单

编辑项目根目录的 `.env`：

```dotenv
QQ_ALLOWED_GROUPS=123456789
```

允许多个群时，用英文逗号分隔：

```dotenv
QQ_ALLOWED_GROUPS=123456789,第二个群号,第三个群号
```

留空表示监听机器人所在的所有群，不推荐：

```dotenv
QQ_ALLOWED_GROUPS=
```

修改 `.env` 后，必须重启 `Video QQ Bot` 才会生效。

配置文件是项目根目录的 `.env`。

```dotenv
# API 和下载服务

# 群白名单
```

配置修改后需要重启对应服务。最简单的方式是打开 `机器人管理.cmd`，先选择 `2`，再选择 `1`。

## 九、常见问题

### NapCat 显示 `ECONNREFUSED 127.0.0.1:8081`

原因：QQ Bot 没有运行，或者启动失败。

处理：

```powershell
cd E:\video_analysis
.\.venv\Scripts\python.exe -m qq_bot.run
```

保持窗口打开并查看报错。正常启动后等待 NapCat 自动重连。

### 浏览器打不开 `127.0.0.1:8000`

原因：转换 API 没有运行。

处理：

```powershell
cd E:\video_analysis
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

### PowerShell 提示“禁止运行脚本”

不要直接运行内部 PowerShell 脚本，改用：

```powershell
.\机器人管理.cmd
```

不需要修改系统 ExecutionPolicy。

### 机器人能看到消息但没有反应

依次检查：

1. 群号是否存在于 `.env` 的 `QQ_ALLOWED_GROUPS`；
2. 修改 `.env` 后是否重启了 QQ Bot；
3. 消息里是否包含 `bilibili.com`、`b23.tv`、`x.com/.../status/...`、`twitter.com/.../status/...`、`v.douyin.com`、`douyin.com/video/...` 或 `api.xiaoheihe.cn/.../share?...link_id=...` 链接；
4. QQ Bot 窗口是否收到事件或显示异常；
5. 同一链接是否在五分钟内已经处理过。

### 机器人回复“服务连接失败”

检查 8000 端口的 API 窗口是否仍在运行。QQ Bot 不能单独完成下载转换。

### 视频转换成功但发送失败

常见原因包括：

- 文件超过 `QQ_MAX_VIDEO_MB`；
- QQ/NapCat 对视频大小或格式有限制；
- 账号被临时限流；
- NapCat 无法访问 `BILI_PUBLIC_API_URL`；
- 视频编码不被 QQ 客户端接受。

先查看 QQ Bot 和 NapCat 两边的日志。不要连续高频重试，以免触发账号风控。

### 端口被占用

查询 8000 和 8081：

```powershell
Get-NetTCPConnection -State Listen | Where-Object LocalPort -in 8000,8081 |
  Select-Object LocalAddress,LocalPort,OwningProcess
```

关闭旧进程后重新启动。NapCat 的反向 WebSocket URL必须与 `QQ_BOT_PORT` 一致。

## 十一、安全和使用边界

NapCatQQ 是非官方协议实现，可能受 QQ 客户端更新影响，并存在账号风控风险。建议：

- 使用专用 QQ 账号；
- 始终配置群白名单；
- 不要高频重复下载和发送；
- 不要把 NapCat WebUI token 公开；
- 不要把 8000、8081、6099 端口直接暴露到公网；
- 只下载、转换和传播你有权使用的内容。

## 十二、Nintendo Switch 在线状态通知

机器人可以在群友开始玩游戏或切换游戏时，向群里发送一张深色状态卡：

```text
[左侧游戏封面] [头像] [正在游玩] [Switch / PS]
                    群友昵称
                    游戏名称
```

状态卡尺寸为 640×220，只显示游戏封面、NS 头像、在线状态、昵称和游戏名，
不显示累计游玩时间、在线人数或今日能力等统计信息。
平台胶囊位于绿色“正在游玩”右侧：Switch 使用红底 `Switch`，PlayStation 使用蓝底 `PS`。

### 平台限制

Nintendo Switch Online 接口通常不能读取登录账号自己的 presence。常见做法是使用另一个 Nintendo Account 作为“观察账号”，让它与需要视奸的人互加 NS 好友。每位被视奸者还需要在 Switch 好友设置中允许这个观察账号查看在线状态和游玩记录。

这套接口并非 Nintendo 面向第三方公开的正式 API，可能随 Nintendo 更新失效。使用前应取得群友同意，不要在对方不知情时视奸或公开其在线状态。

### 推荐的数据来源：nxapi Presence URL

1. 打开 <https://nxapi-auth.fancy.org.uk/>；
2. 按网站说明登录并关联 Nintendo Account；
3. 将观察账号与要视奸的 NS 账号互加好友；
4. 被视奸者允许观察账号查看在线状态/游玩记录；
5. 在 nxapi-auth 中生成或复制该用户的 Presence URL；
6. Presence URL 视同密码，不要发到群里、截图公开或提交到 Git。

也可以自行运行 nxapi HTTP server，使用本机 `http://127.0.0.1:端口/.../presence` 地址。出于安全考虑，机器人仅允许公网 HTTPS，HTTP 只允许 `127.0.0.1`、`localhost` 或 `::1`。

### 配置文件

编辑项目根目录的 `switch_presence.json`：

```json
{
  "enabled": true,
  "poll_interval_seconds": 60,
  "notify_groups": ["123456789"],
  "people": [
    {
      "name": "群里的称呼",
      "presence_url": "https://nxapi-presence.fancy.org.uk/api/presence/替换为真实值",
      "notify_groups": []
    }
  ]
}
```

字段说明：

| 字段 | 说明 |
|---|---|
| `enabled` | `true` 开启视奸，`false` 关闭 |
| `poll_interval_seconds` | 查询间隔，建议 60 秒；程序最低限制为 30 秒 |
| `notify_groups` | 默认通知群号，可以填写多个；当前配置包含 `123456789` 和 `123456789` |
| `people[].name` | 群里显示的称呼，不必等于 NS 昵称 |
| `people[].presence_url` | 该用户的敏感 Presence URL |
| `people[].notify_groups` | 该用户单独通知的群；留空继承默认群号 |

多人配置示例：

```json
{
  "enabled": true,
  "poll_interval_seconds": 60,
  "notify_groups": ["123456789"],
  "people": [
    {
      "name": "小明",
      "presence_url": "https://example.invalid/小明的真实Presence地址",
      "notify_groups": []
    },
    {
      "name": "小红",
      "presence_url": "https://example.invalid/小红的真实Presence地址",
      "notify_groups": ["123456789"]
    }
  ]
}
```

保存后重启 `Video QQ Bot`，或打开 `机器人管理.cmd`，先选择 `2`，再选择 `1`。

正常启动时 QQ Bot 窗口会显示：

```text
Switch presence monitoring started for 1 people
Switch presence baseline ready for 群里的称呼
```

首次查询只建立当前状态基线，不会把所有正在玩游戏的人刷屏。之后只在以下情况通知：

- 从未玩游戏/离线变为开始某个游戏；
- 从一个游戏切换到另一个游戏。

停止游戏或离线不会发送通知，但会重置内部状态，以便下次开始游戏时再次通知。

### 暂时关闭 Switch 视奸

把配置改为：

```json
"enabled": false
```

然后重启 QQ Bot。B 站和 X 视频转换功能不受影响。

### 常见问题

#### 一直显示离线

- 确认观察账号与被视奸者互为 NS 好友；
- 检查被视奸者是否允许该账号查看在线状态；
- 检查“游玩记录”可见范围；
- 确认 Presence URL 没有过期或被撤销；
- 某些用户设置为完全隐藏时，机器人无法绕过隐私设置。

#### 有文字但没有图片

头像或游戏封面 URL 可能临时不可访问，也可能被 NapCat/QQ 下载失败。查看 NapCat 日志中的图片下载错误；文字通知仍会正常发送。
Nintendo CDN 图片会优先直连，失败后才尝试系统代理，避免失效代理导致 TLS 连接错误。

#### 配置后完全没有轮询日志

确认文件名是项目根目录下的 `switch_presence.json`，且 `enabled` 为 `true`、`people` 至少有一项。修改后必须重启 QQ Bot。

#### Presence URL 泄露

立即在 nxapi-auth 中撤销/重新生成 URL，然后更新 `switch_presence.json`。该文件已加入 `.gitignore`，不要手动取消忽略。

## 十三、群聊好友码指令

除手工配置 Presence URL 外，机器人还支持由群友直接登记自己的 NS 好友码。该模式使用一个已经登录 nxapi 的“观察账号”，自动发送好友申请；对方同意后进入视奸。

### 第一次使用前：登录观察账号

先安装官方持续更新的 `next` 构建。公共 npm 的稳定标签 `1.6.1` 是旧构建，可能出现
`Remote configuration prevents Coral authentication`：

```powershell
npm install --global nxapi@next
```

然后打开 `机器人管理.cmd`，选择 `7`。

按照终端和浏览器提示登录“观察账号”。不要使用购买了大量数字游戏的主账号，建议专门创建一个观察账号。

登录过程可能要求把浏览器最终跳转得到的回调地址复制回终端。这个地址、
`session_token_code` 和 `session_token` 都等同登录凭据，只能粘贴到本机 nxapi 终端，
不要发到 QQ 群、聊天工具或截图中。脚本只有在 `nso auth` 和 `nso user` 都成功后才会显示登录成功。

完成后打开 `机器人管理.cmd`，选择 `1` 启动机器人。

在允许的群中检查：

```text
/switch status
```

成功时会回复观察账号当前的 Switch 好友数量。

### 群友命令

添加视奸并发送好友申请：

```text
/switch add SW-1234-5678-9012
/switch add SW-1234-5678-9012 群友昵称
```

`/switch add` 产生的处理中提示、成功结果和错误提示都会引用回复原始指令，确保群里多人
同时添加时能看出每条结果属于哪位指令发送者。

也接受不带 `SW-` 的格式：

```text
/switch add 1234-5678-9012
```

执行流程：

1. 验证好友码格式；
2. 使用 nxapi 查询该账号的 NS 昵称和头像；
3. 观察账号向对方发送好友申请；
4. 将好友码、NSA ID、发起者 QQ 和群号保存到本地 SQLite；
5. 在对方同意前显示“等待同意好友申请”；
6. 同意后自动变为“视奸中”；
7. 开始或切换游戏时，向原群发送头像、游戏名和游戏封面。

同一个好友码可以登记到多个群。若该好友码已经在其他群登记，机器人会复用本地的
NSA ID、昵称和头像，只新增当前群的记录，不会重复发送 Nintendo 好友申请。若本地没有记录，
但观察账号已经与对方成为 NS 好友，机器人也会直接加入本群视奸列表。
新群记录第一次轮询时，如果好友已经在游戏中，也会立即向这个新群补发当前状态卡；
若 QQ 发送失败，记录会保持待发送状态并在下一轮重试。

查看本群列表：

```text
/switch list
/switch nickname SW-1234-5678-9012 群友昵称
```

可能的输出：

```text
本群 Switch 视奸列表：
1. 小明（1234-5678-9012）— 等待同意好友申请
2. 小红（9876-5432-1098）— 视奸中，当前《Mario Kart World》
```

取消自己的视奸：

```text
/switch remove SW-1234-5678-9012
```

`remove` 只删除机器人本地的视奸登记，不会删除 Nintendo Switch 好友关系。
无论普通成员、群管理员还是群主，都只能移除由自己最初登记的账号，不存在管理员越权删除。

查看帮助：

```text
/switch help
```

### 防滥用规则

- 指令只在 `.env` 的 `QQ_ALLOWED_GROUPS` 白名单群生效；
- 同一个好友码不能在同一群重复登记；
- 每位群成员可以登记多个好友码，也可以代其他群友添加；
- 观察账号发送好友申请属于真实的外部操作，应确保好友码由本人自愿提交；
- 不要用机器人批量骚扰陌生好友码。

轮询间隔默认 60 秒，最低限制为 30 秒：

```dotenv
SWITCH_POLL_INTERVAL=60
```

登记数据保存在：

```text
E:\video_analysis\data\switch_registry.db
```

这是 SQLite 数据库，机器人重启后不会丢失，且已经加入 `.gitignore`。

### 常见错误

#### “观察账号尚未登录”

停止 QQ Bot，打开 `机器人管理.cmd`，选择 `7`。

登录完成后打开 `机器人管理.cmd`，选择 `1`。

#### “Remote configuration prevents Coral authentication”

这是旧 nxapi 构建被官方远程配置禁止继续模拟旧版 Nintendo Switch Online 客户端，
不是好友码或 QQ Bot 配置错误。不要通过关闭 remote config 绕过保护。执行：

```powershell
npm install --global nxapi@next
```

安装完成后打开 `机器人管理.cmd`，选择 `7`。

必须重新生成并粘贴一条新的回调地址；旧的 `session_token_code` 是一次性的。

如果已经升级到 `next`，远程配置返回成功，但日志停在
`fetching protected resource metadata`、`znca-auth`、OAuth、fetch 或 timeout，先查看
<https://nxapi-status.fancy.org.uk/>。这是 nxapi 的外部认证/f-generation 服务不可用，
等待状态恢复后再打开 `机器人管理.cmd`，选择 `7`；不要反复生成回调地址，也不要关闭 remote config。

如果错误为 `502 Bad Gateway`，且响应包含 `retryable: true`、`owner_action_required: true`，
可以确定是 nxapi 服务端故障。即使终端已经打印了 `Session token`，只要后面没有出现
`Login and verification succeeded`，机器人就没有保存有效登录。不要复制或复用终端中打印的
token，等待服务恢复后从新的登录链接重新开始。`switch-login.cmd` 会在登录前访问公开的
OAuth 元数据端点进行预检；端点不是 HTTP 200 时不会再生成 Nintendo 登录链接。

日常 `/switch add` 的只读好友码查询遇到 `fetch failed`、`ECONNRESET`、TLS 断开或
502/503/504 时，会按 2 秒、5 秒的间隔自动重试两次。发送好友申请属于外部写操作，
不会盲目自动重试，以免重复提交。后台轮询失败只记录一行简短警告，并在下个周期继续。

#### “TypeError: Invalid state”

回调地址属于某一次唯一的登录会话。每次启动 `switch-login.cmd` 都会生成新的随机 `state`，
旧网页、旧回调和新终端不能混用。按以下步骤重新操作：

1. 关闭所有旧的 Nintendo 登录标签页和旧的 `switch-login.cmd` 窗口；
2. 只启动一次 `switch-login.cmd`；
3. 只打开这个终端刚刚打印的新登录网址；
4. 在最终页面右键“Select this person”，复制链接地址；
5. 把以 `npf71b963c1b7b6d119://auth` 开头的原始链接直接粘贴回同一个终端；
6. 不要从 QQ、Markdown 或聊天记录中复制，因为其中的下划线可能被转义；
7. 一旦失败，关闭该网页，下一次必须从新终端打印的新网址重新开始。

不要把回调地址发出来让别人检查；`state` 可以在本机完成校验，不需要公开链接。

#### 回调地址或 session token 被发到聊天中

立刻登录 Nintendo Account 网站，进入“登录与安全设置”→“登录历史”，选择
“从所有设备登出”；如果凭据发到了其他人可见的位置，同时修改密码并启用两步验证。
完成后重新运行 `switch-login.cmd`。不要把新回调地址再次发送出来。

#### 好友申请已发送但一直是 pending

- 请对方打开 Switch 的好友申请页面并手动同意；
- 确认同意的是观察账号发出的申请；
- 使用 `/switch status` 检查 nxapi 登录是否仍有效；
- Nintendo 好友状态同步可能有几十秒延迟。

#### 群友换了好友码或登记错了

先执行 `/switch remove 旧好友码`，然后重新执行 `/switch add 新好友码`。

## 十四、PS5/PSN 在线状态通知

机器人也可以视奸 PS4 和 PS5 玩家。群友登记 PSN 在线 ID 后，机器人会通过一个专用
PSN 观察账号读取对方公开的在线状态。当玩家开始游戏
或切换游戏时，在登记过该玩家的每个群发送一张与 Switch 相同风格的活动卡片：

- 游戏封面；
- PSN 头像；
- PSN 在线 ID；
- 当前游戏名称。

不会发送累计游玩时间、在线人数或其他统计信息。PS4 游戏和在 PS5 上运行的 PS4 游戏
同样可以识别。

### 安全说明

此功能使用非官方、逆向得到的 PSN 接口。建议单独准备一个 PSN 观察账号，不要使用
购买了大量数字游戏的主账号。PSNAWP 会自动限制请求频率，但仍应避免高频查询。

NPSSO 等同 PSN 账号密码，只能粘贴到机器人电脑上的 `ps5-login.cmd` 窗口：

- 不要发到 QQ 群；
- 不要粘贴到聊天截图；
- 不要提交到 Git；
- 不要把 `secrets` 文件夹上传到公开网盘。

凭据默认保存在：

```text
E:\video_analysis\secrets\psn-npsso.txt
```

该目录已被 `.gitignore` 忽略。NPSSO/刷新登录通常需要约每两个月重新获取一次，实际
有效期以 Sony 返回结果为准。

### 第一次使用：登录 PSN 观察账号

先安装或更新机器人依赖：

```powershell
cd E:\video_analysis
.\.venv\Scripts\python.exe -m pip install -r requirements-bot.txt
```

然后完成登录：

1. 在浏览器打开 PlayStation 官网，使用专用观察账号登录；
2. 保持同一个浏览器登录状态，打开
   <https://ca.account.sony.com/api/v1/ssocookie>；
3. 页面会显示形如 `{"npsso":"64位字符串"}` 的内容；
4. 打开 `机器人管理.cmd`，选择 `8`；
5. 只粘贴 `npsso` 引号内的 64 位字符串，不要粘贴整段 JSON；
6. 出现 `Login successful` 后重启机器人。

登录成功后打开 `机器人管理.cmd` 并选择 `1`，再在群里输入：

```text
/psn status
```

正常结果只会显示 `PS5 服务正常。`，不会公开观察账号的 PSN 在线 ID。

### 群聊命令

查看帮助：

```text
/psn
```

检查玩家公开状态并登记：

```text
/psn add PSN在线ID
/psn add PSN在线ID 群友昵称
```

例如：

```text
/psn add Player-One
```

机器人先直接读取该玩家的公开 Presence，读取成功后才加入本群视奸列表。如果隐私设置
阻止读取，机器人会 @ 指令发送者并提示：

```text
请把“在线状态和当前游戏”设为所有人可见
```

请目标玩家在 PlayStation 的隐私设置中，把“在线状态和当前游戏”的可见范围改成
“所有人”，然后重新执行 `/psn add PSN在线ID`。

查看本群列表：

```text
/psn list
/psn nickname PSN在线ID 群友昵称
```

取消本群登记：

```text
/psn remove Player-One
```

删除规则与 Switch 一致：只有最初登记这条记录的 QQ 用户可以删除；群主和管理员不会
因此获得删除其他人记录的权限。一个 QQ 用户可以登记多个 PSN 玩家。同一个 PSN 玩家
可以登记到多个群；活动卡片会发送到所有登记过他的群。

### 配置

`.env` 中的默认配置：

```dotenv
PSN_NPSSO_FILE=./secrets/psn-npsso.txt
PS5_POLL_INTERVAL=90
```

`PS5_POLL_INTERVAL` 单位为秒，程序最低限制为 60 秒。机器人使用 PSN 批量 Presence
接口查询所有登记玩家，不会为每个人单独建立后台进程。Presence 没有直接提供游戏封面时，
机器人会根据 `npTitleId` 从 PlayStation 游戏目录补查竖版封面并缓存结果。

Switch 和 PS5 使用两个相互独立的后台监控任务。两个本地登记数据库均使用 SQLite WAL
模式，列表查询不会等待在线状态写入；PSN 的同步网络请求还使用独立工作线程，不会占用
`/switch list`、`/psn list` 等本地命令的执行队列。因此一侧外部服务超时或返回 502 时，
另一侧仍会继续运行。

PS5 登记数据保存在：

```text
E:\video_analysis\data\ps5_registry.db
```

迁移机器人电脑时，需要同时复制这个数据库和 `secrets\psn-npsso.txt`。如果复制登录
凭据后 `/psn status` 仍提示登录失效，就在新电脑重新运行 `ps5-login.cmd`。

### 常见问题

`/psn status` 提示尚未登录：

- 运行 `ps5-login.cmd`；
- 必须使用刚生成的 NPSSO；
- 获取 NPSSO 的页面必须与 PlayStation 登录使用同一个浏览器；
- 登录成功后重启 QQ Bot。

能够找到玩家但无法查看状态：

- 让对方把 PSN 隐私设置里的“在线状态和当前游戏”设为“所有人”；
- 检查双方是否存在屏蔽关系；
- 修改后重新运行 `/psn add PSN在线ID`；
- 稍后再运行 `/psn status` 排除 PSN 临时故障。

`/psn list` 长时间没有回复：

- 先确认 `Video QQ Bot` 窗口仍在运行；
- 确认 NapCat 与 `ws://127.0.0.1:8081/onebot/v11/ws` 已连接；
- 新版本会在终端记录 `PS5 list sent` 以及数据库和总耗时；
- 若看不到这行日志，说明机器人仍在运行旧代码，在 `Video QQ Bot` 窗口按 `Ctrl+C` 后
  打开 `机器人管理.cmd`，选择 `4` 重启 QQ Bot。

群里不会显示 PSN 的原始接口响应、堆栈、本机路径或登录凭据。详细技术异常只保留在
机器人电脑日志中，群内只显示简短中文提示。

## 十五、Steam 在线状态通知

`add` 接受 SteamID64、个人主页链接或自定义 ID。目标资料不公开

`remove` 可以删除当前群内的记录，也可以使用列表里的玩家名称；不会影响其他群。

```text
E:\video_analysis\data\steam_registry.db
```

```dotenv
STEAM_API_KEY_FILE=./secrets/steam-api-key.txt

```

轮询间隔最低为 60 秒。迁移电脑时需要同时复制数据库和两个 API Key 文件。

## 十六、Xbox 在线状态通知

机器人通过观察账号直接读取玩家允许公开访问的 Xbox Presence。

### 1. 登录 Xbox 观察账号

1. 双击 `机器人管理.cmd`，选择 `3`；
2. 点击页面顶部“打开 Xbox 登录”；
3. 在自动打开的微软页面登录用于观察状态的 Xbox/Microsoft 账号；
4. 页面提示成功后重启 QQ Bot，再在群里执行 `/xbox status`。

登录令牌保存在 `secrets\xbox-tokens.json`，可以自动刷新，不需要 Azure 应用、Client Secret、
OpenXBL 手机号验证或 API Key。令牌刷新使用跨进程锁并在继续查询前立即落盘，避免登录窗口和机器人同时刷新造成令牌失效。旧 OpenXBL Key 可以留作备用；机器人默认优先微软直连。

### 2. 群聊指令

```text
/xbox add ExampleXboxPlayer
/xbox add ExampleXboxPlayer 群友昵称
/xbox list
/xbox nickname ExampleXboxPlayer 新昵称
/xbox remove ExampleXboxPlayer
/xbox status
```

Xbox 指令的参数直接使用空格分隔，不再使用英文竖线。无法读取公开状态时，机器人会
提示把 Xbox 的在线状态、当前游戏和游戏历史可见范围设为“所有人”。活动卡显示 Xbox 玩家
头像、当前游戏和绿色 `Xbox` 平台标签；数据也会计入日、周、月排行。

```dotenv
XBOX_TOKENS_FILE=./secrets/xbox-tokens.json
# 可选备用
OPENXBL_API_KEY_FILE=./secrets/openxbl-api-key.txt
XBOX_POLL_INTERVAL=90
```

登记数据保存在 `data\xbox_registry.db`。迁移电脑时应连同这个数据库和
`secrets\xbox-tokens.json` 一起复制；令牌属于敏感凭据，不要发群或上传公开网盘。

## 十七、长期运行与稳定性机制

机器人启动后会分别监督 Switch、PS5、Steam、Xbox 和内部健康检查任务。某个后台任务
因未预料的异常退出时，监督器会在 2～60 秒内自动拉起该任务，不会要求重启整个 QQ Bot。

外部服务连续失败时使用指数退避：

- Switch 好友监控最长退避到 10 分钟；
- PS5 监控最长退避到 15 分钟；
- Xbox 监控最长退避到 15 分钟；
- 视频 API 健康检查最长退避到 5 分钟；
- 第一次错误会立即记录，持续相同故障最多每 5 分钟记录一次，避免刷屏；
- 任意一次查询成功后，立即恢复正常轮询频率。

Python 标准日志与 NoneBot/Loguru 日志统一写入 `data\qq-bot.log`，因此 Switch、PSN、Steam、Xbox 和下载模块的异常都会出现在管理后台日志中。SQLite 登记库使用 WAL 和 10 秒忙等待，降低轮询写入与群命令同时访问时的卡顿。

查看综合状态：

```text
/bot status
```

该命令只读取机器人本地保存的最近健康状态，不会临时调用 Nintendo、PlayStation 或视频
接口，因此外部服务卡顿时也能快速回复。它会显示 QQ/NapCat、视频解析、Switch、PS5、Steam、Xbox
以及当前运行时间，且不会公开观察账号 ID、令牌或本机路径。管理后台的状态区域展示同一份本地健康信息。

健康检查间隔可在 `.env` 调整：

```dotenv
BOT_HEALTH_INTERVAL=30
BOT_HEARTBEAT_INTERVAL=5
```

管理器的“启动整套机器人”还会启动独立的 NapCat/QQ Bot 看门狗。QQ Bot 每 5 秒向
`data\qq-runtime-heartbeat.json` 写入一次应用层心跳。看门狗要求连接连续稳定多个样本，
不会再把 NapCat 每 5 秒出现一次的短暂 TCP 重连误判为恢复：

1. 应用心跳过期或 OneBot 连续断开 90 秒，先自动重启 QQ Bot；
2. 再等待 90 秒仍未恢复，才自动重启 NapCat；
3. 两次操作均设置冷却时间，避免反复重启；
4. 详细动作写入 `data\napcat-watchdog.log`，机器人 UTF-8 日志写入
   `data\qq-bot.log`。

启动脚本会等待最多 20 秒，并实际检查：

- `http://127.0.0.1:8000/health` 是否返回成功；
- QQ Bot 是否已监听 `127.0.0.1:8081`。

若检查失败，启动窗口会明确提示查看哪个日志窗口。看门狗可以恢复意外退出或 WebSocket
假连接，但用户主动结束看门狗、电脑休眠或断电后仍需打开 `机器人管理.cmd` 并选择 `1`，也可以另行配置
Windows 登录后自动启动。
# 批量设置三个平台昵称

如果不想在群聊里逐条输入昵称命令，可以在项目目录中使用批量昵称工具。

1. 双击 `nickname-export.cmd`。工具会读取 Switch、PSN、Steam 当前已经登记的账号，并生成 `昵称绑定.txt`。
2. 用记事本或 Excel 打开 `昵称绑定.txt`，只修改最后一列“昵称”。各列之间使用英文竖线 `|` 分隔，请勿修改平台和 ID。
3. 保存文件后双击 `nickname-import.cmd`。
4. 导入立即生效，不需要重启机器人。同一个平台 ID 如果登记在多个群，只需填写一次，会同步更新所有群。

示例：

```text
平台|ID|示例玩家|昵称
switch|SW-1111-2222-3333|SwitchPlayer|示例玩家
psn|ExamplePSN|ExamplePSN|示例玩家
steam|76561198098765432|SteamPlayer|示例玩家
```

空着昵称表示保持原值；填写 `[清空]` 表示删除该账号的昵称。导入前工具会自动把三个数据库备份到 `data\nickname_backups`，填错时可以恢复。
# 游戏时长排行榜（日、周、月排行）

群内输入以下任一命令：

```text
/rank
/排行
/游戏排行
/今日排行
/rank w
/rank m
/rank m 8
/rank o
/rank o w
/rank o m
/rank o m 8
/rank o move 成员名
/rank o restore 成员名
```

`/rank` 及其中文别名会发送本群今日游戏时长排行榜；`/rank w` 会发送本周排行榜；`/rank m` 会发送本月排行榜；`/rank m 8`
会查询最近一次 8 月的历史月排行（若今年 8 月尚未到来，则自动查询去年 8 月）。日排行从当天
04:00 开始，周排行从本周一 04:00 开始，月排行从当月 1 日 04:00 开始，均统计到对应统计期内最后一次有效记录时间。同一
昵称（忽略英文大小写）下的 Switch、PSN、Steam、Xbox 时长会自动合并，并按照总时长排序；成员内部
的游戏按照单项时长排序。

`/rank o` 是独立的成员组，统计范围、图片样式和游戏屏蔽规则与主榜相同。输入 `/rank o move 成员名`
可将该昵称及其合并的所有平台记录从 `/rank` 移至 `/rank o`；输入 `/rank o restore 成员名` 可恢复到主榜。
成员名支持大小写不敏感的全名以及唯一的部分匹配；匹配到多人时必须输入完整昵称。成员分组按群保存。

如果某个游戏不想出现在排行榜中，可输入 `/rank remove 游戏名`。这只过滤排行榜并重新计算
日、周、月排行中的时长，不会影响 Switch、PSN、Steam、Xbox 的实时游玩播报。游戏名匹配会忽略大小写、空格和标点，并支持包含匹配；例如 `/rank remove TBH` 可屏蔽“TBH 塔斯巴克英雄”。恢复显示请输入 `/rank add 游戏名`。

时长记录保存在 `data\game_time.db`。首次启用后，第一轮只建立当前游戏基线，第二轮起开始
累计。超过 5 分钟的轮询空档不会计入，以免网络故障、平台服务故障或电脑休眠导致时长虚增。
阈值可通过 `.env` 的 `GAME_TIME_MAX_SAMPLE_GAP` 调整，单位为秒。

发售日自动提醒默认在每天 09:00 后检查“明日发售”和“今日发售”的游戏，并发送到 `QQ_ALLOWED_GROUPS` 中的所有群。提醒成功记录在数据库中，因此机器人重启后不会重复发送。可在管理后台调整提醒小时、提前天数（默认 `1,0`）和检查间隔；修改后重启 QQ Bot 生效。
